## The encoder, and the one layer that matters

<CodeWalk title="Spatial softmax">

```python title="policy.py"
import torch, torch.nn as nn, torchvision

class SpatialSoftmax(nn.Module):
    """(B, C, H, W) feature maps -> (B, 2C) expected keypoint coordinates."""

    def __init__(self, height, width, temperature=1.0):
        super().__init__()
        self.temperature = temperature
        ys, xs = torch.meshgrid(
            torch.linspace(-1, 1, height),
            torch.linspace(-1, 1, width),
            indexing="ij",
        )
        # Buffers, not parameters: the coordinate grid is fixed geometry.
        self.register_buffer("xs", xs.reshape(-1))
        self.register_buffer("ys", ys.reshape(-1))

    def forward(self, feat):
        B, C, H, W = feat.shape
        # Softmax over SPACE (the flattened H*W axis), not over channels.
        attn = torch.softmax(feat.reshape(B, C, H * W) / self.temperature, dim=-1)
        x = (attn * self.xs).sum(-1)          # (B, C) expected column
        y = (attn * self.ys).sum(-1)          # (B, C) expected row
        return torch.cat([x, y], dim=-1)      # (B, 2C)
```

</CodeWalk>

`dim=-1` is the whole layer. Softmax over the channel axis would give you a
per-pixel classification of "which feature is this"; softmax over the spatial
axis gives you a per-feature distribution of "where is it". The second is a
keypoint detector; the first is not.

## Wiring it together

<CodeWalk title="Per-view encoder, shared head">

```python title="policy.py"
def make_encoder():
    net = torchvision.models.resnet18(weights="IMAGENET1K_V1")
    # Small, correlated policy batches make batch statistics unreliable.
    net = replace_bn_with_gn(net)
    return nn.Sequential(*list(net.children())[:-2])   # drop avgpool + fc


class VisuomotorPolicy(nn.Module):
    def __init__(self, n_views, prop_dim, act_dim, chunk=8, feat_hw=(7, 7)):
        super().__init__()
        # One encoder PER VIEW: a wrist camera and an overhead camera see
        # different distributions, and sharing weights forces a compromise.
        self.encoders = nn.ModuleList([make_encoder() for _ in range(n_views)])
        self.pool = SpatialSoftmax(*feat_hw)

        vis_dim = n_views * 2 * 512
        self.act_dim, self.chunk = act_dim, chunk
        self.head = nn.Sequential(
            nn.Linear(vis_dim + prop_dim, 512), nn.ReLU(),
            nn.Linear(512, 512), nn.ReLU(),
            nn.Linear(512, act_dim * chunk),
        )

    def forward(self, views, prop):               # views: list of (B, 3, H, W)
        feats = [self.pool(enc(v)) for enc, v in zip(self.encoders, views)]
        z = torch.cat(feats + [prop], dim=-1)     # proprioception joins HERE
        return self.head(z).view(-1, self.chunk, self.act_dim)
```

</CodeWalk>

Proprioception is concatenated after pooling, not painted onto the image as
extra channels. Joint angles have no spatial extent, and a policy given an easy
proprioceptive shortcut will take it — training loss falls, vision is ignored,
and the robot fails the moment the object moves.

## Augmentation, done correctly

```python title="augment.py"
def random_crop_views(views, pad=8):
    """One offset per sample, shared across camera views."""
    B = views[0].shape[0]
    dx = torch.randint(0, 2 * pad + 1, (B,))
    dy = torch.randint(0, 2 * pad + 1, (B,))

    out = []
    for v in views:
        v = nn.functional.pad(v, (pad,) * 4, mode="replicate")
        # Same (dx, dy) for every view: the cameras are rigidly mounted, and
        # independent offsets would train invariance to a shift that cannot
        # physically happen.
        out.append(torch.stack([
            v[b, :, dy[b]:dy[b] + views[0].shape[2],
                    dx[b]:dx[b] + views[0].shape[3]] for b in range(B)
        ]))
    return out
```

<Warning>
Augment the training half only, and split by episode rather than by timestep.
Both mistakes inflate validation numbers in the same direction, and together
they produce the classic report: "validation loss 0.003, success rate 15%."
</Warning>

## What to measure

<Steps>
<Step title="Rollout success, under a visual change you did not train on">
Move a lamp, swap the table covering, nudge a camera. A policy that survives
that has learned the task; one that does not has learned the room. This is the
only evaluation that predicts deployment.
</Step>

<Step title="Where the keypoints land">
Spatial softmax outputs are image coordinates, so overlay them on the frame.
Keypoints tracking the object and the gripper mean the encoder found the task;
keypoints pinned to a table corner mean it found a shortcut. This is the one
piece of interpretability an end-to-end policy hands you for free — use it.
</Step>

<Step title="Blank the image and re-run">
Feed zeros or a shuffled frame and measure how much success drops. Barely at all
means the policy is running on proprioception and the vision pathway is
decorative.
</Step>
</Steps>
