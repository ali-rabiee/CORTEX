## The randomisation config

<CodeWalk title="Structured ranges with calibrated nominals">

```python title="config.py"
from dataclasses import dataclass

@dataclass
class Range:
    lo: float
    hi: float
    step: float          # how much ADR grows or shrinks it per resize


# Multiplicative around measured nominals, so "±30%" transfers across robots.
DYNAMICS = {
    "mass_scale":     Range(0.95, 1.05, 0.05),
    "friction_scale": Range(0.90, 1.10, 0.05),
    "motor_kp_scale": Range(0.95, 1.05, 0.05),
    "latency_steps":  Range(0.0,  1.0,  1.0),     # the cheapest large win
}

# Visuals get wide ranges from the start: appearance is an input you can
# flood with variation, and there is no performance cost to over-covering it.
VISUAL = {
    "light_intensity": Range(0.3, 2.0, 0.1),
    "texture_id":      Range(0, 1000, 50),
    "camera_pos_cm":   Range(-1.0, 1.0, 0.5),
}
```

</CodeWalk>

Note the asymmetry: dynamics ranges start tight and grow, visual ranges start
wide. Over-randomising appearance costs almost nothing because the policy can
simply learn to ignore it; over-randomising dynamics costs performance directly,
because it demands one strategy work across incompatible physics.

## Automatic Domain Randomisation

<CodeWalk title="Boundary sampling and the resize rule">

```python title="adr.py"
import numpy as np
from collections import defaultdict, deque

class ADR:
    def __init__(self, ranges, p_boundary=0.5, lo_thresh=0.3, hi_thresh=0.7,
                 buffer_size=20):
        self.ranges = {k: [r.lo, r.hi] for k, r in ranges.items()}
        self.step = {k: r.step for k, r in ranges.items()}
        self.p_boundary, self.lo, self.hi = p_boundary, lo_thresh, hi_thresh
        # One buffer per (dimension, which end) — resizing on a single noisy
        # episode return would thrash the ranges.
        self.buffers = defaultdict(lambda: deque(maxlen=buffer_size))

    def sample(self, rng):
        xi = {k: rng.uniform(*v) for k, v in self.ranges.items()}
        if rng.random() > self.p_boundary:
            return xi, None

        # ONE dimension at a boundary. With everything at its extreme the
        # return says only that the joint worst case is hard, and no
        # individual range can be credited or blamed.
        dim = rng.choice(list(self.ranges))
        end = rng.integers(2)
        xi[dim] = self.ranges[dim][end]
        return xi, (dim, end)

    def update(self, tag, success):
        if tag is None:
            return
        buf = self.buffers[tag]
        buf.append(float(success))
        if len(buf) < buf.maxlen:
            return

        dim, end = tag
        mean = np.mean(buf)
        sign = -1 if end == 0 else +1        # widen: lower end down, upper up
        if mean > self.hi:
            self.ranges[dim][end] += sign * self.step[dim]
            buf.clear()
        elif mean < self.lo:
            self.ranges[dim][end] -= sign * self.step[dim]
            buf.clear()

    def entropy(self):
        """The progress metric. Mean return stays flat by construction —
        the curriculum holds difficulty at the edge of ability — so what
        you watch is how much variation the policy has come to tolerate."""
        return float(np.mean([np.log(hi - lo + 1e-8)
                              for lo, hi in self.ranges.values()]))
```

</CodeWalk>

<Warning>
A flat mean-return curve is the *expected* signature of a healthy ADR run, not a
plateau. The curriculum deliberately keeps difficulty pinned between the two
thresholds, so return should hover there while the support grows underneath it.
Log `entropy()` per dimension; a dimension whose range has stopped growing is
telling you either that the policy cannot absorb more of that variation, or that
your step size for it is too large.
</Warning>

## Sampling rates encode what a quantity is

```python title="env.py"
def reset(self):
    # PER EPISODE: properties of the setup that persist for the whole run.
    self.xi = adr_sample()                       # physics parameters
    self.cam_bias = rng.normal(0, 0.005, 3)      # calibration offset
    self.latency = int(self.xi["latency_steps"])
    self.action_queue = [np.zeros(self.act_dim)] * (self.latency + 1)
    return self._obs()

def _obs(self):
    raw = self.sim.get_obs()
    # PER STEP: genuinely stochastic, nothing to infer.
    noise = rng.normal(0, self.obs_noise_std, raw.shape)
    return raw + self.cam_bias + noise           # persistent bias + fresh noise
```

<KeyIdea>
Resampling a persistent quantity per step converts it from an inferable hidden
variable into white noise. The policy can then only average over it, which
silently downgrades an adaptive setup into a robust one — and the training
curves look identical either way. This is the most consequential
five-line decision in a randomisation implementation.
</KeyIdea>

## Verifying the randomisation is doing what you think

<Steps>
<Step title="Hold out a range and evaluate outside it">
Train on $[0.9, 1.1]$, evaluate at $1.2$. A cliff just outside the support means
the policy interpolated rather than generalised — informative, and it tells you
reality had better be inside.
</Step>

<Step title="Per-dimension ablation">
Fix one dimension at its nominal and re-evaluate. Dimensions whose removal
changes nothing are costing you performance for no transfer benefit, and can be
narrowed or dropped.
</Step>

<Step title="Check that history is being used">
For an adaptive policy, feed it a constant history — zeros, or a shuffled one —
and measure the drop. Near zero means the policy is ignoring history and you
have a robust policy wearing an adaptive architecture.
</Step>

<Step title="Probe identifiability directly">
Train a small probe to predict $\xi$ from the policy's internal latent. If the
probe cannot, the policy has not identified the environment, and no amount of
extra history will make it adaptive — the excitation is not there.
</Step>
</Steps>
