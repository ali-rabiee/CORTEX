## The same trainer, three different loops

All three share an inner supervised or RL update. What differs is what each loop
is allowed to touch.

<CodeWalk title="The three families, side by side">

```python title="families.py"
# --- 1. Behaviour cloning: a dataset and nothing else -------------------
def behaviour_cloning(policy, dataset, train):
    return train(policy, dataset)          # no env, no expert. That's it.


# --- 2. DAgger: + environment, + queryable expert -----------------------
def dagger(policy, env, expert, train, iterations=10):
    dataset = []
    for i in range(iterations):
        obs, done = env.reset(), False
        while not done:
            dataset.append((obs, expert(env.state)))   # <- needs the expert
            obs, _, done, _ = env.step(policy.act(obs))
        policy = train(fresh_policy(), dataset)
    return policy


# --- 3. GAIL: + environment, + RL, + discriminator ----------------------
def gail(policy, env, expert_data, rl_update, disc, disc_opt, iterations=1000):
    for _ in range(iterations):
        rollout = collect(policy, env)                  # <- needs rollouts

        # Discriminator learns to tell learner from expert...
        loss = bce(disc(rollout), 0) + bce(disc(expert_data), 1)
        disc_opt.zero_grad(); loss.backward(); disc_opt.step()

        # ...and its confusion becomes the policy's reward.
        rewards = -torch.log(1 - disc(rollout) + 1e-8)
        policy = rl_update(policy, rollout, rewards)    # <- needs an RL loop
    return policy
```

</CodeWalk>

<KeyIdea>
Read the function signatures, not the bodies. `behaviour_cloning(dataset)`,
`dagger(env, expert)`, `gail(env, rl)`. The arguments *are* the trade-off — each
extra parameter is a resource you must actually possess.
</KeyIdea>

## Triage in practice

Before arguing about which method is better, establish which are even available:

<Steps>
<Step title="Do you have a simulator or safe rollouts?">
No → everything requiring environment interaction is out. That removes GAIL and
the RL step inside most IRL methods, leaving cloning and offline RL.
</Step>

<Step title="Can you query the expert at arbitrary states?">
No → DAgger is out. Yes, and it's code rather than a person → DAgger is probably
your best option.
</Step>

<Step title="Do your demonstrations carry rewards, or include failures?">
Yes → offline RL becomes available, and unlike cloning it can beat the average
demonstration by stitching good segments together.
</Step>

<Step title="Only then compare quality">
Among what survives, pick on the failure mode you actually observe: drift over
the horizon, or a repeatable failure where demonstrations disagree.
</Step>
</Steps>

<Warning>
A common interview answer is "I'd use GAIL because it fixes distribution shift."
It does — and it needs an RL loop's worth of environment interaction to do it,
which on real hardware is usually the resource you have least of. Stating the
cost alongside the benefit is most of the signal.
</Warning>
