## The two loops

<CodeWalk title="Impedance control at 1 kHz">

```python title="impedance.py"
import numpy as np

class CartesianImpedance:
    """Runs at ~1 kHz. The policy never sees this loop; it only sets x_d and K.

    K comes from a force budget, not from tuning: to tolerate F_max newtons at
    the position error you actually expect, K = F_max / e_expected. Five newtons
    at 2 mm is 2500 N/m — far below the arm's native position-control stiffness,
    which is the entire point.
    """
    def __init__(self, K, damping_ratio=1.0, m_eff=1.0):
        self.K = np.asarray(K, float)
        # Critical damping: overshoot in contact means an impact.
        self.D = 2.0 * damping_ratio * np.sqrt(self.K * m_eff)

    def wrench(self, x, xdot, x_d, xdot_d=0.0):
        return self.K * (x_d - x) + self.D * (xdot_d - xdot)

    def torque(self, J, x, xdot, x_d, q, qdot, gravity):
        # Gravity compensation is separate: it must be exact regardless of the
        # impedance, or the arm sags and the setpoint means something else.
        return J.T @ self.wrench(x, xdot, x_d) + gravity(q)
```

</CodeWalk>

Critical damping matters more here than in free space: an overshoot against a
stiff surface is an impact, and the peak force during an impact is not bounded by
$K\delta$ at all.

## What the policy actually emits

<CodeWalk title="Setpoint and stiffness as the action space">

```python title="action.py"
import numpy as np

K_MIN, K_MAX = 100.0, 3000.0          # N/m, per axis
DELTA_MAX = 0.01                      # m, per policy step

def decode(a, x_now):
    """a in [-1, 1]^6: three for the setpoint delta, three for log-stiffness.

    The policy says WHERE to aim and HOW FIRMLY to insist. It does not say what
    force to apply — at 10 Hz that command would be held across contact events
    lasting 1 ms, which is how you get the forces compliance was meant to avoid.
    """
    x_d = x_now + np.clip(a[:3], -1, 1) * DELTA_MAX
    # Log-space so the policy can span a decade of stiffness with uniform
    # resolution; linear interpolation would spend most of its range near K_MAX.
    t = (np.clip(a[3:], -1, 1) + 1.0) / 2.0
    K = K_MIN * (K_MAX / K_MIN) ** t
    return x_d, K
```

</CodeWalk>

Low stiffness on the axes that must comply, high on the axes that must make
progress — a policy that learns to *lower* stiffness laterally while inserting
axially has discovered the same structure a remote-centre-of-compliance device
implements mechanically.

## Force, aggregated rather than sampled

<CodeWalk title="Summarising a 1 kHz signal for a 10 Hz consumer">

```python title="obs.py"
class ForceWindow:
    """One sample per policy step is a random draw from a 100 ms window, and a
    1 ms impact is invisible to it except by luck. Three statistics answer three
    different questions the policy has."""

    def __init__(self, contact_threshold=2.0):
        self.buf, self.thr = [], contact_threshold

    def push(self, f):            # called from the fast loop
        self.buf.append(float(np.linalg.norm(f)))

    def summarize(self):
        b = np.asarray(self.buf) if self.buf else np.zeros(1)
        self.buf = []
        return np.array([
            b.max(),                       # did anything get hit
            b.mean(),                      # sustained loading
            float((b > self.thr).mean()),  # tap vs. press
        ])
```

</CodeWalk>

## Search when the tolerance is below the uncertainty

<CodeWalk title="Compliant spiral, with contact as the measurement">

```python title="search.py"
def spiral_insert(robot, ctrl, x0, radius=0.004, pitch=0.0004,
                  push=6.0, drop=0.002, timeout=20.0):
    """Sweeps the uncertainty disc while compliance bounds the forces.

    The success test is axial position, not force: when the peg finds the hole
    it descends. That is a direct observation of alignment, available precisely
    where a pose estimate has run out of resolution.
    """
    ctrl.K = np.array([800., 800., 3000., 50., 50., 50.])   # soft laterally
    theta, z0 = 0.0, x0[2]
    while robot.elapsed() < timeout:
        r = min(pitch * theta / (2 * np.pi), radius)
        x_d = x0 + np.array([r * np.cos(theta), r * np.sin(theta),
                             -push / ctrl.K[2]])
        robot.step(ctrl, x_d)
        if z0 - robot.x()[2] > drop:
            return True
        theta += 0.25
    return False
```

</CodeWalk>

<Warning>
Two failure modes hide in this stack. Gravity compensation must stay exact
independently of the impedance — otherwise lowering stiffness makes the arm sag
and every setpoint silently means something else, which reads as "the policy got
worse at low stiffness". And a stiffness so low the arm cannot overcome its own
friction turns the setpoint into a suggestion: the commanded motion stops
happening at all, which looks like a policy failure rather than an actuation
limit.
</Warning>
