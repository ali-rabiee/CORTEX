## The entire training loop

Nothing here is specific to robots. If you removed the variable names, this
would look like any regression script.

<CodeWalk title="Behaviour cloning, end to end">

```python title="train_bc.py"
import torch
import torch.nn as nn

class BCPolicy(nn.Module):
    """Observation -> a chunk of k future actions."""

    def __init__(self, obs_dim, act_dim, chunk=1, hidden=512):
        super().__init__()
        self.act_dim, self.chunk = act_dim, chunk
        self.net = nn.Sequential(
            nn.Linear(obs_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, act_dim * chunk),
        )

    def forward(self, obs):                       # obs: (B, obs_dim)
        out = self.net(obs)                       # (B, act_dim * chunk)
        return out.view(-1, self.chunk, self.act_dim)


def train(policy, loader, act_mean, act_std, epochs=100, lr=1e-4):
    opt = torch.optim.AdamW(policy.parameters(), lr=lr, weight_decay=1e-4)

    for _ in range(epochs):
        for obs, act in loader:                   # act: (B, chunk, act_dim)
            # Put every action dimension on the same scale, or MSE is
            # dominated by whichever one has the largest physical units.
            target = (act - act_mean) / act_std

            pred = policy(obs)
            loss = nn.functional.mse_loss(pred, target)

            opt.zero_grad()
            loss.backward()
            opt.step()
```

</CodeWalk>

The three lines that matter are the normalisation, the MSE, and the `chunk`
reshape. Everything else is boilerplate you would write for any regressor.

## The dataset is where the thinking happens

<Steps>
<Step title="Flatten trajectories into pairs">
Demonstrations arrive as episodes. Index into them so that item $i$ is one
observation and the $k$ actions that followed it. Near the end of an episode,
pad the chunk by repeating the final action.
</Step>

<Step title="Compute normalisation statistics once, over the whole dataset">
Save `act_mean` and `act_std` alongside the weights. Recomputing them per batch
is a real bug — it makes the target a moving goalpost, and inference has no
batch to compute them from.
</Step>

<Step title="Hold out whole episodes, never individual timesteps">
Consecutive frames are nearly identical. A random per-timestep split puts
near-duplicates in both train and validation, and your validation loss becomes
meaningless — it will look excellent while the policy fails on the robot.
</Step>
</Steps>

<Warning>
Low validation loss is *not* evidence that behaviour cloning will work. It
measures accuracy on the expert's state distribution, which is precisely the
distribution the policy will leave the moment it acts. The only honest
evaluation is rolling the policy out on the task and counting successes.
</Warning>

## Inference

```python title="rollout.py"
@torch.no_grad()
def run_episode(policy, env, act_mean, act_std, chunk=1):
    obs, done, steps = env.reset(), False, 0

    while not done and steps < env.max_steps:
        pred = policy(torch.as_tensor(obs).float().unsqueeze(0))
        actions = (pred[0] * act_std + act_mean).cpu().numpy()  # un-normalise

        # Execute the chunk open-loop, re-planning once it's exhausted.
        for a in actions[:chunk]:
            obs, _, done, _ = env.step(a)
            steps += 1
            if done:
                break
```

Note what's absent: no reward, no value function, no environment interaction
during training. That is the whole appeal — and the whole limitation.
