## Tokenising a robot observation

<CodeWalk title="Heterogeneous inputs into one sequence">

```python title="tokenize.py"
import torch, torch.nn as nn

class MultimodalTokenizer(nn.Module):
    def __init__(self, d_model=512, n_views=2, patch=14, img=224,
                 prop_dim=14, lang_dim=768):
        super().__init__()
        self.n_patches = (img // patch) ** 2                  # 256 per view
        self.patch_proj = nn.Conv2d(3, d_model, kernel_size=patch, stride=patch)
        self.prop_proj = nn.Linear(prop_dim, d_model)
        self.lang_proj = nn.Linear(lang_dim, d_model)

        # Positional embeddings say WHERE a token is. Modality embeddings say
        # WHAT KIND it is — without them the model must infer from content that
        # token 300 is a wrist patch and not a word.
        self.modality_emb = nn.Parameter(torch.zeros(3, d_model))   # img/prop/lang
        self.view_emb = nn.Parameter(torch.zeros(n_views, d_model))
        self.pos_emb = nn.Parameter(torch.zeros(1, 2048, d_model))

    def forward(self, images, proprio, lang_feats):
        toks = []
        for v, img in enumerate(images):                       # each (B,3,H,W)
            p = self.patch_proj(img).flatten(2).transpose(1, 2)  # (B, 256, d)
            toks.append(p + self.modality_emb[0] + self.view_emb[v])

        toks.append(self.prop_proj(proprio).unsqueeze(1) + self.modality_emb[1])
        toks.append(self.lang_proj(lang_feats) + self.modality_emb[2])

        x = torch.cat(toks, dim=1)
        return x + self.pos_emb[:, : x.shape[1]]
```

</CodeWalk>

Count what came out: 512 visual tokens, one proprioception token, a handful of
language tokens. Vision is the whole budget, and attention cost grows with its
square — halve the visual tokens and the attention cost drops by roughly four.

## Learned action queries

<CodeWalk title="The decoder-side pattern that makes this a policy">

```python title="policy.py"
class ActionDecoder(nn.Module):
    """H learned query vectors, one per predicted action.

    The queries are PARAMETERS — identical on every forward pass, carrying no
    input information. Query k learns 'what do I need to know to produce the
    k-th action from now', and all observation content arrives via attention.
    """

    def __init__(self, d_model=512, n_heads=8, n_layers=4, H=16, act_dim=7):
        super().__init__()
        self.queries = nn.Parameter(torch.randn(H, d_model) * 0.02)
        layer = nn.TransformerDecoderLayer(
            d_model, n_heads, dim_feedforward=4 * d_model,
            batch_first=True, norm_first=True,       # pre-norm: far more stable
        )
        self.decoder = nn.TransformerDecoder(layer, n_layers)
        self.head = nn.Linear(d_model, act_dim)

    def forward(self, obs_tokens):                   # (B, n_obs, d)
        B = obs_tokens.shape[0]
        q = self.queries.unsqueeze(0).expand(B, -1, -1)   # (B, H, d)
        # NO causal mask among the queries. The whole chunk is emitted in one
        # pass from one observation, so there is no generation order to respect,
        # and letting later actions inform earlier ones is what makes the chunk
        # coherent as a motion.
        out = self.decoder(tgt=q, memory=obs_tokens)
        return self.head(out)                        # (B, H, act_dim)
```

</CodeWalk>

<Warning>
`norm_first=True` is not cosmetic. Post-norm transformers — the original
formulation — need a learning-rate warmup to train at depth, and without it they
diverge. Pre-norm puts the residual path in the clear and trains stably from
step one. Almost every model since 2020 uses it, and copying an old
implementation is a reliable way to spend a day on a warmup schedule.
</Warning>

## Attention, without materialising the matrix

```python title="attention.py"
import torch.nn.functional as F

def mha(x, q_proj, k_proj, v_proj, o_proj, n_heads, attn_mask=None):
    B, N, D = x.shape
    h, dk = n_heads, D // n_heads

    # (B, h, N, dk) — heads become a batch dimension.
    q = q_proj(x).view(B, N, h, dk).transpose(1, 2)
    k = k_proj(x).view(B, N, h, dk).transpose(1, 2)
    v = v_proj(x).view(B, N, h, dk).transpose(1, 2)

    # Dispatches to a fused kernel and never materialises the (B,h,N,N)
    # attention matrix — which is the memory bottleneck, not the FLOPs.
    # The 1/sqrt(dk) scaling is applied internally.
    out = F.scaled_dot_product_attention(q, k, v, attn_mask=attn_mask)

    return o_proj(out.transpose(1, 2).reshape(B, N, D))
```

<KeyIdea>
The $n \times n$ attention matrix is what runs you out of memory, not the
parameter count. At 512 tokens, 8 heads, batch 64, a materialised matrix is tens
of millions of entries per layer held for the backward pass. Fused
implementations recompute it in tiles instead, which is usually the difference
between a batch size of 8 and a batch size of 64.
</KeyIdea>

## Masking, concretely

```python title="masks.py"
def chunk_policy_mask(n_obs, H, device):
    """Action queries: see all observations, and see each other freely.
    Observation tokens: do not attend to action queries.
    """
    n = n_obs + H
    m = torch.zeros(n, n, device=device)
    m[:n_obs, n_obs:] = float("-inf")     # obs must not read the queries
    return m                              # queries<->queries left OPEN


def temporal_causal_mask(n_steps, tokens_per_step, device):
    """Across time, causality is real: step t cannot see step t+1."""
    n = n_steps * tokens_per_step
    step_of = torch.arange(n, device=device) // tokens_per_step
    return torch.where(step_of[None, :] > step_of[:, None],
                       torch.tensor(float("-inf"), device=device),
                       torch.tensor(0.0, device=device))
```

## Checks worth running

<Steps>
<Step title="Count your tokens before anything else">
Print the sequence length. If a policy is slow, this number explains it more
often than the parameter count does, and it is the only lever with a quadratic
effect.
</Step>

<Step title="Visualise attention from an action query">
Reshape the weights over visual tokens back to the patch grid and overlay them.
Queries attending to the object and the gripper mean the model found the task;
queries fixed on a table corner mean it found a shortcut — the same diagnostic
as spatial-softmax keypoints, and the main interpretability an attention policy
gives you.
</Step>

<Step title="Ablate each modality at inference">
Zero the language tokens, then the wrist view, then proprioception, and measure
the drop. A modality whose removal changes nothing is costing you tokens —
quadratically — for no benefit.
</Step>
</Steps>
