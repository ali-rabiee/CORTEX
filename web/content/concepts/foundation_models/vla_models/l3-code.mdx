## Tokenising actions

<CodeWalk title="Quantile binning, and reusing the language vocabulary">

```python title="action_tokenizer.py"
import numpy as np

class ActionTokenizer:
    """Continuous actions <-> token ids, occupying unused vocabulary slots."""

    def __init__(self, dataset_actions, n_bins=256, vocab_size=32000):
        # Quantiles, not min-max: a handful of teleop glitches would otherwise
        # stretch the range so that all normal actions land in a few bins.
        self.lo = np.percentile(dataset_actions, 1, axis=0)   # (d,)
        self.hi = np.percentile(dataset_actions, 99, axis=0)
        self.n_bins = n_bins
        # Overwrite the least-frequent language tokens. No new embeddings,
        # no resized softmax — the model does not know these are special.
        self.offset = vocab_size - n_bins

    def encode(self, actions):                     # (..., d) -> (..., d) ids
        a = np.clip(actions, self.lo, self.hi)
        frac = (a - self.lo) / (self.hi - self.lo + 1e-8)
        idx = np.clip((frac * self.n_bins).astype(int), 0, self.n_bins - 1)
        return idx + self.offset

    def decode(self, token_ids):                   # ids -> bin centres
        idx = np.clip(token_ids - self.offset, 0, self.n_bins - 1)
        frac = (idx + 0.5) / self.n_bins           # centre, not edge
        return self.lo + frac * (self.hi - self.lo)
```

</CodeWalk>

Two details. The `+ 0.5` decodes to the bin *centre*, which halves the expected
error against decoding to the edge. And `offset` is what makes this free: the
action tokens are ordinary vocabulary entries, so the embedding table, the
attention, and the softmax head are all untouched and the pretrained weights
transfer without surgery.

## The inference loop, and where the time goes

<CodeWalk title="Autoregressive action decoding">

```python title="infer.py"
@torch.no_grad()
def predict_chunk(model, tokenizer, image, instruction, H=8, d=7):
    # Prefill: ONE pass over image patches + instruction tokens. Expensive,
    # but paid once per chunk.
    prompt = model.build_prompt(image, instruction)
    kv_cache = model.prefill(prompt)

    tokens = []
    for _ in range(H * d):
        # H*d SEQUENTIAL passes through a 7B backbone. This term dominates
        # total latency by an order of magnitude — everything that makes a
        # VLA fast attacks the H*d multiplier, not the parameter count.
        logits = model.decode_step(kv_cache)
        tokens.append(logits.argmax(-1))

    ids = torch.stack(tokens).view(H, d)
    return tokenizer.decode(ids.cpu().numpy())     # (H, d) continuous actions


def run(model, tokenizer, env, instruction, H=8, T_a=4):
    obs, done = env.reset(), False
    while not done:
        chunk = predict_chunk(model, tokenizer, obs["image"], instruction, H=H)
        # Receding horizon: execute T_a of H, then re-plan with a fresh image.
        for a in chunk[:T_a]:
            obs, _, done, _ = env.step(a)
            if done:
                break
```

</CodeWalk>

<Warning>
Quote your latency as a budget, not a number:
$T_{\text{prefill}} + H d\,T_{\text{decode}}$, amortised over $T_a$ executed
actions. Every design choice in this area is a move inside it — longer $H$ with
larger $T_a$, parallel decoding of action tokens (giving up within-chunk
autoregressive dependency), compressing the chunk so fewer tokens represent it,
or replacing the decode loop with a small continuous head the backbone
conditions once.
</Warning>

## Co-fine-tuning

```python title="train.py"
# The web term is not regularisation in the usual sense — it is what keeps the
# model able to do the thing you adopted it for. Drop it and you get a model
# that has learned your demonstrations and forgotten what a mug is.
for step in range(num_steps):
    robot_batch = next(robot_loader)
    web_batch = next(web_loader)

    loss_robot = model.lm_loss(robot_batch.prompt, robot_batch.action_tokens)
    loss_web = model.lm_loss(web_batch.prompt, web_batch.text_tokens)
    loss = loss_robot + WEB_WEIGHT * loss_web

    loss.backward(); opt.step(); opt.zero_grad()
```

The evaluation that catches a missing web term is not held-out demonstration
loss — that looks fine. It is performance on objects and phrasings outside the
robot dataset, which is the only place forgetting shows up.

## Adapting to a new task

<CodeWalk title="LoRA on the attention projections">

```python title="adapt.py"
from peft import LoraConfig, get_peft_model

# 300 demonstrations cannot support updating 7B parameters. Full fine-tuning
# at this scale fits the demos perfectly and loses the generalisation you
# adopted the model for — visible only on out-of-set objects and phrasings.
config = LoraConfig(
    r=32, lora_alpha=64, lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
)
model = get_peft_model(base_vla, config)
model.print_trainable_parameters()   # typically well under 1% of the total
```

<Steps>
<Step title="Evaluate outside the fine-tuning distribution, always">
Held-out demonstrations from the same session do not test what you care about.
Swap the object, rephrase the instruction, change the lighting. Full fine-tuning
at small data scale characteristically looks excellent on the first and collapses
on the second.
</Step>

<Step title="Check the action-token distribution">
Histogram the emitted bins. Mass piled at bin 0 or bin 255 means your quantile
range is too narrow and actions are being clipped; mass concentrated in a few
central bins means it is too wide.
</Step>

<Step title="Ablate the language input">
Feed an empty or scrambled instruction and measure the drop. Near zero means the
policy is ignoring language and you have an expensive unconditional policy —
the same conditioning-sensitivity check that applies to any multi-task policy.
</Step>
</Steps>
