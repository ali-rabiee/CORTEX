## Mixing heterogeneous datasets

<CodeWalk title="Cross-embodiment sampling with an explicit weighting">

```python title="mixture.py"
import numpy as np

def temperature_weights(dataset_sizes, temperature=0.7):
    """Pooling and shuffling weights by dataset size, which in a cross-lab
    corpus mostly reflects which institution had more robots and more funding.
    Temperature < 1 keeps large datasets dominant without letting a
    500-episode embodiment vanish entirely.
    """
    sizes = np.asarray(dataset_sizes, dtype=float)
    w = sizes ** temperature
    return w / w.sum()


class MixtureSampler:
    def __init__(self, datasets, weights, seed=0):
        self.datasets = datasets
        self.weights = np.asarray(weights) / np.sum(weights)
        self.rng = np.random.default_rng(seed)

    def __iter__(self):
        while True:
            i = self.rng.choice(len(self.datasets), p=self.weights)
            ds = self.datasets[i]
            yield ds[self.rng.integers(len(ds))], i     # keep the embodiment id
```

</CodeWalk>

The returned embodiment index is not bookkeeping. It selects the normalisation
statistics and becomes the conditioning token, and losing it is how a pooled
corpus quietly becomes an averaged one.

## Per-embodiment normalisation

```python title="normalize.py"
class EmbodimentStats:
    """Workspace size and control rate differ between robots, so a 5 cm delta
    means something different on a tabletop arm and a mobile manipulator.
    Pooled statistics normalise nobody correctly."""

    def __init__(self, datasets):
        self.stats = []
        for ds in datasets:
            acts = np.concatenate([ep.actions for ep in ds])
            lo = np.percentile(acts, 1, axis=0)      # quantiles, not min-max:
            hi = np.percentile(acts, 99, axis=0)     # teleop glitches have tails
            self.stats.append((lo, hi))

    def encode(self, action, embodiment_id):
        lo, hi = self.stats[embodiment_id]
        a = np.clip(action, lo, hi)
        return 2 * (a - lo) / (hi - lo + 1e-8) - 1   # -> [-1, 1]

    def decode(self, normed, embodiment_id):
        lo, hi = self.stats[embodiment_id]
        return (normed + 1) / 2 * (hi - lo) + lo
```

<Warning>
Save these alongside the weights and treat them as part of the deployed policy.
A checkpoint restored with normalisation statistics recomputed on a newer corpus
revision produces actions scaled by the wrong constants, which presents as a
subtly worse policy rather than as a bug — the single most expensive quiet
failure in this pipeline.
</Warning>

## Co-fine-tuning

<CodeWalk title="Interleaving web and robot batches">

```python title="cofinetune.py"
def train_step(model, robot_iter, web_iter, opt, web_weight=0.5):
    """The web term anchors the shared backbone to the pretrained solution
    along the directions that solution depends on. It is not weight decay —
    it references a SPECIFIC prior solution, which is the one containing the
    semantics you adopted the model for.
    """
    (obs, instr, action), emb_id = next(robot_iter)
    action_tokens = tokenizer.encode(action, emb_id)

    loss_robot = model.lm_loss(
        prompt=model.build_prompt(obs, instr, embodiment=emb_id),
        target=action_tokens,
    )

    web_images, web_text = next(web_iter)
    loss_web = model.lm_loss(
        prompt=model.build_prompt(web_images, web_text.prompt),
        target=web_text.target,
    )

    (loss_robot + web_weight * loss_web).backward()
    opt.step(); opt.zero_grad()
    return {"robot": loss_robot.item(), "web": loss_web.item()}
```

## The evaluation that catches forgetting

<CodeWalk title="Stratify by what the pretraining was supposed to buy">

```python title="eval_strata.py"
STRATA = {
    # In the robot data. Looks fine even when the model has forgotten
    # everything it was adopted for.
    "seen_object_seen_instruction":  (SEEN_OBJECTS,  SEEN_INSTRUCTIONS),

    # Objects the robot data never contained. Isolates the transferred
    # semantic capability — this is the column that moves.
    "novel_object_seen_instruction": (NOVEL_OBJECTS, SEEN_INSTRUCTIONS),

    # Same objects, different words. Isolates language generalisation from
    # visual generalisation.
    "seen_object_new_phrasing":      (SEEN_OBJECTS,  REPHRASED),

    # Both. The claim people actually make about VLAs.
    "novel_object_new_phrasing":     (NOVEL_OBJECTS, REPHRASED),
}


def evaluate(policy, robot, n_per_stratum=25):
    out = {}
    for name, (objects, instructions) in STRATA.items():
        scenes = build_scenes(objects, instructions, n=n_per_stratum, seed=0)
        results = [robot.rollout(policy, s).success for s in scenes]
        k, n = sum(results), len(results)
        out[name] = {"rate": k / n, "ci": wilson(k, n), "n": n}
    return out
```

</CodeWalk>

<KeyIdea>
A single aggregate success rate cannot distinguish a model that borrowed
successfully from one that has forgotten and is compensating with demonstration
fit. The four-way split can, and it maps directly onto the claim being made — so
the stratification should be decided from the claim, before any numbers exist.
</KeyIdea>

<Steps>
<Step title="Why the from-scratch control matters">
Without it, "the model handles novel objects" could be explained by scale,
architecture, or the action head. With it, the difference is attributable to the
pretraining specifically.
</Step>

<Step title="Why the robot-only control matters">
It separates *having* the pretrained initialisation from *keeping* it. A model
initialised from a VLM and fine-tuned without a web term often looks like the
from-scratch model on out-of-set evaluation, which is the whole argument for the
mixture.
</Step>
</Steps>
