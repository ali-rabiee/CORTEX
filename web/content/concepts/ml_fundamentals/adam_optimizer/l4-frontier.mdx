## The original, and the property that mattered

<PaperCard refKey="kingma2015adam" />

Momentum for the direction, per-coordinate second-moment normalisation for the
scale, and a bias correction for the zero initialisation. What most summaries
omit — and the paper states explicitly — is the signal-to-noise reading: the
update $\hat m/\sqrt{\hat v}$ estimates $\mu/\sqrt{\mu^2+\sigma^2}$, bounded in
$[-1,1]$.

<KeyIdea>
That reading explains the adoption. It makes the update **scale-invariant per
coordinate**, so a single learning rate works across layers whose gradients differ
by orders of magnitude, and it makes the learning rate a distance in parameter
space rather than a multiplier on an unknown gradient scale. Robustness, not
speed, is what made Adam the default.
</KeyIdea>

## The criticism that did not stick

<PaperCard refKey="reddi2018amsgrad" />

A genuine flaw: the exponential moving average of the second moment can *forget* a
large past gradient, so the effective learning rate can increase, and on a
constructed convex problem Adam fails to converge. AMSGrad's fix is to take a
running maximum of $v$, making the effective rate monotonically non-increasing.

<Warning>
The analysis is correct and the fix is rarely used. The failure mode it targets
is not what limits Adam on the problems people actually train, and the fix is
conservative — a running maximum never forgets, so adaptation slows permanently
after any large gradient.

Worth citing whenever someone treats a convergence guarantee as evidence about
behaviour. A valid theoretical result still needs its practical relevance
established separately, and here it was not.
</Warning>

## The criticism that did

<PaperCard refKey="loshchilov2019adamw" />

L2 regularisation in the loss adds $\lambda\theta$ to the gradient, which then
passes through the $1/\sqrt{\hat v}$ scaling — so the effective decay is
inversely proportional to gradient magnitude, and the parameters doing the most
work are regularised the least.

<Steps>
<Step title="Why this one was adopted">
It happens on every run, not on a constructed problem. Every model trained with
L2-in-the-loss under Adam was silently getting non-uniform regularisation.
</Step>

<Step title="And the fix costs nothing">
Two lines, no extra state, no slower adaptation, no new hyperparameter. A correct
diagnosis of a universal problem with a free fix is adopted; a correct diagnosis
of a rare problem with a costly fix is not.
</Step>

<Step title="Why it went unnoticed for years">
Under plain SGD the two forms are equivalent up to a factor of $\eta$. The
distinction only exists once the optimiser is adaptive, so it was invisible for
the whole period during which the equivalence was learned.
</Step>
</Steps>

## The pressure since: memory and simplicity

<PaperGrid>
<PaperCard refKey="shazeer2018adafactor" />
<PaperCard refKey="chen2023lion" />
</PaperGrid>

Adam stores two tensors the size of the parameters. At 16 bytes per parameter in
fp32, a 7B model is 112 GB of parameters, gradients, and optimiser state before
any activations — so the state is a first-class cost, not an implementation
detail.

Adafactor attacks it directly, factoring the second-moment matrix into row and
column statistics so state drops from $O(nm)$ to $O(n+m)$ per weight matrix. The
approximation is that the second moment is approximately rank one, which holds
well enough in practice.

Lion attacks it differently: keep only momentum, and take the **sign** of an
interpolation between the gradient and the momentum.

<KeyIdea>
Lion's competitiveness is informative about Adam. The update $\hat m/\sqrt{\hat v}$
already tends to $\pm 1$ for consistent gradients, so if taking the sign outright
works nearly as well, the second moment's main contribution was *producing* that
boundedness rather than encoding useful per-coordinate curvature — with the
residual benefit being graded damping of noisy coordinates. That halves the
optimiser state, which at 7B parameters is 28 GB.
</KeyIdea>

## What is settled and what is not

<Steps>
<Step title="Settled">
Decoupled weight decay. Bias correction. That the learning rate is a distance in
parameter space, which is why Adam's hyperparameters transfer. That normalisation
gains and biases should be excluded from decay.
</Step>

<Step title="Contested">
Whether adaptive methods generalise worse than well-tuned SGD with momentum on
some problems. The effect is real enough on some vision benchmarks to be taken
seriously and small enough that it rarely justifies the tuning burden — the honest
answer is that it depends on the problem and is worth measuring if you are chasing
the last point.
</Step>

<Step title="Open">
Whether the second moment is needed at all, given that sign-based methods with
half the state are competitive. And whether any of this survives at the next
scale, where optimiser memory increasingly dominates the design.
</Step>
</Steps>
