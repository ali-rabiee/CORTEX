## Not "the chain rule" — a particular order of it

Backpropagation is usually introduced as applying the chain rule to a network,
which is true and skips the content. The chain rule is a product of Jacobians:

$$
\frac{\partial L}{\partial x} = \frac{\partial L}{\partial h_n}\,\frac{\partial h_n}{\partial h_{n-1}}\cdots\frac{\partial h_1}{\partial x}
$$

Matrix products are **associative**, so you can evaluate this left-to-right or
right-to-left — and the two orders cost enormously different amounts.

<Figure src="/figures/backprop-mode-choice.svg"
        alt="Top: forward mode propagating derivatives left to right, costing one pass per parameter. Bottom: reverse mode propagating right to left, costing one pass for a scalar loss, with a table showing checkpointing memory reductions."
        caption="The chain rule can be evaluated in either associative order. Which one is cheap depends entirely on the shape of the function — few outputs and many inputs makes reverse mode the right choice by orders of magnitude." />

<Steps>
<Step title="Right-to-left is forward mode">
Start at the input and carry $\partial(\text{everything})/\partial x_i$ forward.
Each pass gives the derivative with respect to **one input**, so a scalar loss of
$10^9$ parameters needs $10^9$ passes.
</Step>

<Step title="Left-to-right is reverse mode">
Start at the loss and carry $\partial L/\partial(\text{everything})$ backward.
Each pass gives the derivatives of **one output** with respect to everything, so a
scalar loss needs one pass — for all $10^9$ gradients.
</Step>
</Steps>

<KeyIdea>
Deep learning is computationally feasible because losses are scalars. That is not
a coincidence of notation — it is the structural fact that makes the cheap
direction the useful one. If you needed the full Jacobian of a network's outputs
with respect to its parameters, none of this would work.
</KeyIdea>

<Intuition>
Tracing responsibility through an organisation. Forward mode asks "if this one
person had worked differently, what would have changed everywhere?" — and you
must ask it once per person.

Reverse mode asks "this outcome was bad; how much did each person contribute?" —
one question, answered for everyone at once, by working backwards from the
outcome.
</Intuition>

## The price

The backward pass needs the intermediate activations, because the local Jacobians
depend on them — the derivative of a ReLU depends on whether its input was
positive, and the gradient with respect to a weight matrix depends on the layer's
input. Those are computed forwards, so they must be **kept** until the backward
pass reaches them.

<Warning>
This is why a model whose weights fit comfortably still runs out of memory during
training. Parameters are fixed; activations scale with batch size and sequence
length, and there is one set per layer held for the whole forward pass. Activation
memory, not parameter count, is what caps your batch size — and diagnosing an
out-of-memory error by looking at the model size is the most common way to spend
an afternoon on the wrong problem.
</Warning>

## Buying the memory back

Store only every $\sqrt{L}$-th activation and recompute the rest when the
backward pass needs them:

| layers | stored | memory |
| --- | --- | --- |
| 12 | 7 | 58% |
| 32 | 11 | 35% |
| 96 | 20 | 20% |

<KeyIdea>
The cost is about one extra forward pass — roughly 30% more compute — and the
result is **exact**. Nothing is approximated; the recomputed activations are
identical. It is the same trade FlashAttention makes one level down: spend the
abundant resource to save the scarce one, and in transformer training the scarce
one is almost always memory.
</KeyIdea>

## What you never compute

A Jacobian of a $d = 4096$ linear layer is $4096\times4096$ — 64 MiB in fp32, per
example. Nobody forms it.

Backpropagation computes **vector-Jacobian products**: given the gradient flowing
in, it produces the gradient flowing out, without ever materialising the matrix
between them. For a linear layer that is just another matrix multiply by the
transpose. Every operation in a framework ships with a rule for this product
rather than for its Jacobian, which is why autograd is memory-feasible at all.

## Where it breaks

The backward pass multiplies Jacobians together, and a long product of matrices
either grows or shrinks exponentially unless something holds it in check.

<Steps>
<Step title="Vanishing">
Repeated multiplication by factors below 1 drives early-layer gradients to zero,
so those layers stop learning. This is what made deep networks untrainable before
residual connections.
</Step>

<Step title="Exploding">
Factors above 1 do the opposite, and the symptom is a loss that jumps to `NaN`.
Gradient clipping is the blunt fix and works well.
</Step>

<Step title="What actually solved it">
Residual connections, because $\partial(x + F(x))/\partial x = I + J$ contains an
identity — so the product across layers has a term that passes through no
multiplicative factor at all. That is the structural fix, and normalisation and
careful initialisation are what keep the remaining factors near 1.
</Step>
</Steps>
