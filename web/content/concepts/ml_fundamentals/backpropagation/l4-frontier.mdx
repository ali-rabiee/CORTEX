## Older than its fame

Reverse-mode automatic differentiation was developed in the numerical computing
literature well before neural networks adopted it — the algorithm is not what
1986 contributed.

<PaperCard refKey="rumelhart1986backprop" />

What that paper established is what backpropagation made *possible*: that a
network could learn useful internal representations in its hidden layers rather
than requiring them to be designed. The algorithm was the vehicle; the claim was
about representation learning.

<KeyIdea>
Worth getting right in an interview, because "who invented backprop" has a
contested answer and "what did the 1986 paper show" has a clear one. The
algorithm has multiple independent origins in numerical analysis and control; the
demonstration that it makes hidden-layer representation learning work is the
contribution being cited.
</KeyIdea>

## The framing that clears up the confusion

<PaperCard refKey="baydin2018ad" />

Automatic differentiation is routinely confused with two other things, and both
confusions have practical consequences.

<Steps>
<Step title="It is not symbolic differentiation">
Symbolic differentiation manipulates expressions and suffers expression swell —
the derivative of a modestly nested function can be enormous to write down. AD
evaluates numerically at a point, composing local rules, so nothing grows.
</Step>

<Step title="It is not finite differences">
Finite differences approximate, with a truncation error and a step size to
choose, and cost one evaluation per input. AD is **exact** to floating-point
precision and costs a constant factor over the forward pass.
</Step>

<Step title="Why that matters practically">
It tells you a failed gradient check indicates a bug rather than expected
numerical error. If AD were approximate you would have to decide what tolerance
is acceptable; because it is exact, a real discrepancy means a wrong backward
rule.
</Step>
</Steps>

The survey also derives the forward/reverse cost asymmetry properly — one pass
per input versus one per output — which is what makes backpropagation an instance
of a general principle rather than a trick specific to neural networks.

## Turning a constraint into a trade

<PaperCard refKey="chen2016checkpointing" />

Reverse mode's cost is that every activation must survive until the backward pass
reaches it, and for a long time that was simply a limit on how large a model you
could train.

Checkpointing converts it: store a $\sqrt L$-spaced subset, recompute the rest.
Memory falls from $O(L)$ to $O(\sqrt L)$ — 96 layers to about 20 stored
activations — for roughly one extra forward pass.

<Warning>
The property that makes this adoptable is exactness. The recomputed activations
are the same computation, so there is no accuracy question to argue about and it
can be switched on whenever memory is tight. Compare an approximate method, which
would need defending per application — the same adoption asymmetry that decided
the efficient-attention question.
</Warning>

## The same trade, one level down

<PaperCard refKey="dao2022flashattention" />

FlashAttention applies checkpointing's logic inside a single operation: never
write the $n\times n$ attention matrix, and recompute tiles in the backward pass.
It uses *more* arithmetic than the naive implementation and is substantially
faster, because the binding resource was memory bandwidth.

<KeyIdea>
The transferable rule: any intermediate that exists only because the naive
execution order happened to compute it is a candidate for recomputation. Modern
accelerators are far more starved of memory bandwidth than of arithmetic, so
spending FLOPs to avoid a write is usually a good trade — and checkpointing and
FlashAttention are the same idea at two granularities.
</KeyIdea>

## Where the pressure is now

Reverse mode's memory requirement is what shapes distributed training, and the
connection is direct rather than incidental.

<Steps>
<Step title="Optimiser state sharding">
Not a backprop consequence, but the same memory budget. At 16 bytes per parameter
in fp32, a 7B model's parameters, gradients and Adam state are 112 GB before any
activation exists.
</Step>

<Step title="Activation offload and recomputation">
Directly a backprop consequence. Activations can be moved to host memory and
fetched back, or recomputed — the same trade as checkpointing with a different
resource on the other side.
</Step>

<Step title="Pipeline parallelism and the bubble">
Cutting a model across devices creates a bidirectional dependency: activations
travel forward, gradients travel back, and the cut point must hold its activation
in between. Devices idle across that gap, which is the pipeline bubble — and
micro-batching and interleaved schedules exist entirely to fill it.
</Step>
</Steps>

<Warning>
Almost every complication in large-scale training traces to one fact: the
backward pass needs the forward pass to still exist. That is the price of the
associative order that makes gradients cheap, and it is worth being able to state
the connection — it turns a list of distributed-training techniques into
consequences of a single design choice.
</Warning>
