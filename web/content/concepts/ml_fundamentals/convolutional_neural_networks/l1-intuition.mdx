## The prior is weight sharing

A convolutional layer applies the same kernel at every spatial position. That is
not an implementation convenience — it is a claim about the world: **a feature
means the same thing wherever it appears**.

<Figure src="/figures/cnn-receptive-field.svg"
        alt="Left: a comparison showing a 3x3 256-channel convolution using 589,824 parameters against 644 billion for a dense equivalent. Right: a table of receptive field size against depth for stride-1, strided, and dilated convolutions."
        caption="Reusing one kernel everywhere is a million-fold parameter reduction and a correct prior about images. It also means context grows linearly with depth, which is far slower than it feels." />

<KeyIdea>
For a $3\times3$ layer mapping 256 channels to 256 on a $56\times56$ grid, the
convolution has about 590 thousand parameters and a dense layer over the same
activations would have 644 *billion* — a factor of $10^6$. That reduction is
purchased entirely by the assumption, and it is why convolutional networks were
trainable on datasets that could never have supported the dense equivalent.
</KeyIdea>

<Intuition>
Learning to recognise a face by learning a separate detector for every possible
position in the image is absurd — you would need as many examples as positions.
Learning one detector and sliding it is obviously right.

Obviously right *for images*. It is exactly wrong for something like a tabular
problem where each column means something different, and it is why applying
convolutions to arbitrary data is not a neutral choice.
</Intuition>

## Equivariance, and its weaker cousin

Weight sharing gives **translation equivariance**: shift the input and the output
shifts with it. That is a property of the convolution and it holds exactly.

<Warning>
Equivariance is not invariance, and the distinction matters more than it sounds.
Equivariance says the output *moves with* the input; invariance says the output
*does not change*. Convolution gives the first; pooling and global averaging give
approximate versions of the second.

Which you want depends on the task, and getting it backwards is a real design
error. Classification wants invariance — a cat is a cat wherever it is.
Segmentation, detection, and any robot policy that must reach toward something
want **equivariance**, because where it is *is the answer*. Global average
pooling in a manipulation policy destroys exactly the information the task needs,
which is why spatial softmax exists.
</Warning>

## Context grows slowly

Each stride-1 $3\times3$ layer adds 2 to the receptive field, so after $L$ layers
it is $1 + 2L$ — **linear** in depth.

| layers | stride 1 | stride 2 alternating | dilated |
| --- | --- | --- | --- |
| 2 | 5 | 5 | 7 |
| 4 | 9 | 13 | 31 |
| 6 | 13 | 29 | 127 |
| 10 | 21 | 125 | 2047 |

<KeyIdea>
Ten layers of plain $3\times3$ convolution see 21 pixels. That is much less than
most people assume, and it means a network cannot relate two objects 50 pixels
apart no matter how many parameters it has. Context is not something depth
provides for free — it has to be bought.
</KeyIdea>

<Steps>
<Step title="Striding and pooling — multiplicative growth">
Each downsample doubles how far a subsequent layer reaches, so the field grows
geometrically. The cost is resolution: you cannot localise more precisely than
the grid you are working on.
</Step>

<Step title="Dilation — exponential growth at full resolution">
Insert gaps between kernel taps and double the gap each layer. Eight layers reach
511 pixels while every layer stays at full resolution — which is why it dominates
in segmentation, where you need both context and precise boundaries.
</Step>

<Step title="Attention — global in one layer, at quadratic cost">
Every position sees every other immediately. The convolutional constraint
disappears and is replaced by a different one: cost that grows with the square of
the number of positions.
</Step>
</Steps>

## When the prior stops paying

A built-in inductive bias is a constraint. It helps when data is scarce, because
it is structure you did not have to learn, and it limits you when data is
plentiful, because the learned version fits better.

<Warning>
That crossover is measured rather than argued: vision transformers, which discard
translation equivariance entirely, lose to convolutions at ImageNet scale and win
with much larger pretraining. So the question is never "convolution or
transformer" but **how much data do I have**.

For a robot policy with 200 demonstrations the answer is emphatic: a
convolutional trunk gives you a correct prior for free, and it pools spatially
before any sequence model, which cuts the token count that attention pays for
quadratically. The one argument that overrides this is wanting to inherit
pretrained weights — which is really a statement that someone else already paid
the data cost.
</Warning>
