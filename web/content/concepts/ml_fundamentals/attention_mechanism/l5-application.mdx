interview:
  answer: >-
    Attention is a soft dictionary lookup. Every position produces a query, a
    key, and a value; you score each query against every key, softmax the scores
    into weights, and the output is the weighted average of the values. The
    consequence worth stating is that every output is a convex combination of
    value vectors, so attention can't create content — it decides what to mix,
    and all the expressiveness lives in the projections that decide what the
    keys and values are. It's also literally Nadaraya-Watson kernel regression
    with an exponential kernel, where the metric is learned rather than fixed,
    which explains why it generalises by interpolation and has no mechanism to
    produce something outside the convex hull of its values. On the scaling
    factor: the dot product of two d-dimensional vectors with unit-variance
    entries has variance d, so unscaled logits grow like root-d — at d equals 64
    that's logits around 8, which saturates the softmax and kills the gradient.
    Dividing by root-d-k restores unit-variance logits at any dimension. Where
    I'd want to correct the usual framing is the cost. Everyone says attention
    is quadratic and therefore expensive, and that points at the wrong resource.
    Attention costs about 2 n-squared d and the feed-forward block costs about
    16 n d-squared, so they cross at n equals eight d — for width 4096, about
    32,000 tokens. Below that attention is a small fraction of the arithmetic:
    1.6 percent at 512 tokens, 6 percent at 2k, 25 percent at 8k. So halving
    attention's FLOPs at typical sequence lengths barely changes training time.
    What actually binds is memory. The n-by-n matrix at 8192 tokens with batch 8
    and 32 heads in fp16 is 32 gigabytes for a single layer, and autograd holds
    it for the backward pass. That's what FlashAttention addresses — it tiles
    the computation, carries a running softmax maximum and denominator so no
    tile needs the global normaliser, and recomputes tiles in the backward pass
    instead of storing them. It computes exact attention and it actually uses
    more FLOPs, and it's faster anyway because GPUs are far more starved of
    memory bandwidth than of arithmetic. That's also why the whole
    sub-quadratic-approximation wave from 2020-21 didn't displace exact
    attention: an asymptotic win in the resource that wasn't binding lost to a
    constant-factor win in the one that was.
  followUps:
    - q: "What about the inference side?"
      a: >-
        Different memory problem, and orthogonal. FlashAttention is about a
        transient intermediate inside one forward pass; at inference there's no
        backward pass, and what accumulates is the KV cache — the keys and
        values of every previous token, held so you don't recompute them per
        generated token. It grows linearly with context and per concurrent
        sequence, and for a 32-layer, 32-head model with head dimension 128 at
        32k context that's about 16 gigabytes per sequence. The fix is sharing
        key-value heads across query heads: grouped-query attention with 8
        groups takes it to 4 gigabytes, multi-query with one shared head to
        about half a gigabyte with a larger quality cost. What I find
        interesting is that this is a serving constraint that propagated back
        into the architecture — models are now designed with fewer KV heads than
        query heads from the start rather than converted afterwards.
    - q: "So is multi-head about capacity?"
      a: >-
        No, and that's worth being precise about, because the parameter count is
        essentially unchanged — h heads of dimension d over h total d. The gain
        is that a single softmax produces exactly one distribution over
        positions per query. So a single-head layer has a query that needs to
        attend to two different things for two different reasons and no choice
        but to blend them into a compromise serving neither. Several heads in
        separate learned subspaces let several relations coexist. It's the same
        one-softmax-one-mode argument that shows up wherever you need to
        represent multiple things at once. The cost is dimension per head — a
        head too narrow can't represent a useful similarity at all, which is why
        d_k is usually kept at 64 or more rather than pushing h up arbitrarily.
    - q: "When would a sub-quadratic method actually be the right choice?"
      a: >-
        When you're genuinely past the crossover, which means sequence lengths
        well beyond eight times the model width — so very long context with a
        modest width, or something like genomics or long audio where n is in the
        hundreds of thousands. There the quadratic term really does dominate the
        arithmetic and the asymptotics start to matter. I'd still want the
        comparison run against FlashAttention rather than against a naive
        baseline, because a lot of the reported speedups in that literature were
        measured against implementations that materialised the matrix. And I'd
        weigh exactness: an exact method needs no quality argument and can be
        adopted by default, while an approximation has to be defended per
        application, which is a real adoption cost that never appears in the
        speedup table.
    - q: "How would you debug an attention layer that isn't learning?"
      a: >-
        First check the logit scale, since that's the failure the scaling factor
        exists to prevent — if someone reimplemented it and dropped the
        1/root-d_k, or the queries and keys aren't roughly unit-variance because
        the norm placement is wrong, the softmax saturates and the gradient
        vanishes. I'd print the attention entropy per head: near-uniform means
        the head isn't discriminating and is just returning an average,
        near-zero means it's saturated. Then the mask, because a causal mask
        applied where it shouldn't be is silent — it doesn't error, it just
        removes information. And I'd check norm placement: post-norm needs a
        learning-rate warmup to train at depth and diverges without one, which
        is a very common inheritance from copying an old implementation.
  traps:

## Reading the symptoms

<Steps>
<Step title="Out of memory at a small batch → the $n^2$ matrix, not the parameters">
$b h n^2 \cdot 2$ bytes in fp16, retained for the backward pass. Use a fused
exact kernel before reducing the batch.
</Step>

<Step title="Slow, and you assumed it was attention → profile the FFN">
Below $n \approx 8d$ the feed-forward block dominates the arithmetic. Optimising
attention there is optimising 6% of the problem.
</Step>

<Step title="Out of memory as concurrency rises at inference → the KV cache">
It accumulates per sequence and per token. Grouped-query attention or cache
quantisation; FlashAttention does not address it.
</Step>

<Step title="Not learning at all → check the logit scale and the mask">
A missing $1/\sqrt{d_k}$, mis-placed norm, or a causal mask applied where it
should not be. None of these error; they just remove the gradient or the
information.
</Step>

<Step title="Diverges early at depth → post-norm without warmup">
Pre-norm trains stably from step one. A common inheritance from copying an older
implementation.
</Step>
</Steps>

<Warning>
The distinguishing move here is correcting the cost framing with numbers.
Everyone can say attention is quadratic; very few can say that at width 4096 it
only matches the feed-forward block's FLOPs at around 32k tokens, that the
binding resource below that is the memory holding the $n^2$ matrix, and that
FlashAttention is faster while using *more* arithmetic. That last point in
particular signals you have profiled one of these rather than read about them —
and the underlying lesson, that an asymptotic win in the wrong resource loses to
a constant-factor win in the right one, generalises well past attention.
</Warning>
