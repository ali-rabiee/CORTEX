## Is variance actually your problem?

<CodeWalk title="Gradient signal-to-noise, in one function">

```python title="diagnose.py"
import torch

def gradient_snr(policy, batch, loss_fn, n_splits=8):
    """||mean gradient|| / mean(||gradient||) over minibatches.

    Near 1: the minibatch gradients agree and you have a consistent direction.
    Near 1/sqrt(n_splits): they are cancelling and you are averaging noise.

    The policy-gradient LOSS value cannot tell you this — it is a surrogate
    whose magnitude carries no information. This can.
    """
    grads = []
    for chunk in batch.split(n_splits):
        policy.zero_grad()
        loss_fn(policy, chunk).backward()
        grads.append(torch.cat([
            p.grad.flatten().clone() for p in policy.parameters() if p.grad is not None
        ]))

    G = torch.stack(grads)
    return (G.mean(0).norm() / G.norm(dim=1).mean()).item()
```

</CodeWalk>

Run this before optimising anything. A ratio near 1 means variance is not your
bottleneck and you should be looking at exploration, reward, or the state
representation instead.

<KeyIdea>
The expected pattern is a large jump from `full_return` to `return_to_go`, a
larger one to `baselined`, and a smaller one to `gae`. If the baseline row does
*not* improve things, your critic is not removing the state-value term — it is
adding noise of its own, and $\lambda$ is the wrong knob to reach for.

## Check the critic before the dial

```python title="critic_health.py"
@torch.no_grad()
def explained_variance(values, returns):
    """1.0 perfect, 0.0 no better than predicting the mean, <0 actively worse.

    A critic near zero is not subtracting the state value — it is subtracting
    noise. Lowering lambda then leans harder on exactly the failing component.
    """
    var_r = returns.var()
    return float("nan") if var_r == 0 else (1 - (returns - values).var() / var_r).item()
```

<Warning>
The ordering matters. Explained variance below about 0.3 means the baseline is
not doing its job, and the correct response is to fix the critic — capacity,
target normalisation, learning rate — or to *raise* $\lambda$ so you depend on it
less. Lowering $\lambda$ is the intuitive move and the wrong one, because it
feeds more of the failing component into every advantage.
</Warning>

## Normalisation: log what it destroys

<CodeWalk title="Raw statistics before, and a running alternative">

```python title="normalize.py"
class AdvantageNormalizer:
    """Per-batch normalisation centres each batch on its OWN mean, so an
    all-good batch and an all-bad batch produce identical weights. In sparse-
    reward or early-termination environments whole batches are routinely
    one-signed — and that is the signal being discarded.
    """

    def __init__(self, mode="batch", decay=0.99):
        self.mode, self.decay = mode, decay
        self.run_mean, self.run_var, self.inited = 0.0, 1.0, False

    def __call__(self, adv, metrics):
        # Log the RAW statistics: this is the only place the level survives.
        metrics["adv_raw_mean"] = float(adv.mean())
        metrics["adv_raw_std"] = float(adv.std())
        metrics["adv_frac_positive"] = float((adv > 0).float().mean())

        if self.mode == "batch":
            return (adv - adv.mean()) / (adv.std() + 1e-8)

        # Running normalisation: fixes the scale drift without destroying the
        # across-batch level, at the cost of a slower-adapting scale.
        m, v = float(adv.mean()), float(adv.var())
        if not self.inited:
            self.run_mean, self.run_var, self.inited = m, v, True
        else:
            self.run_mean = self.decay * self.run_mean + (1 - self.decay) * m
            self.run_var = self.decay * self.run_var + (1 - self.decay) * v
        return (adv - self.run_mean) / (self.run_var ** 0.5 + 1e-8)
```

</CodeWalk>

`adv_frac_positive` is the metric that catches this. Values near 0 or 1 mean the
batch was one-signed, and if that happens often, per-batch normalisation is
throwing away your main signal — switch to the running mode and watch whether
learning starts.

## Off-policy, when actors lag

```python title="vtrace.py"
def vtrace(rewards, values, bootstrap_value, log_rho, gamma,
           clip_rho=1.0, clip_c=1.0, dones=None):
    """Two thresholds because they bound different things:
      clip_c  -- caps the PRODUCT along the trace, whose variance explodes
      clip_rho-- caps the leading ratio, which sets the FIXED POINT
    """
    rho = torch.exp(log_rho).clamp(max=clip_rho)
    c = torch.exp(log_rho).clamp(max=clip_c)

    v_next = torch.cat([values[1:], bootstrap_value[None]])
    nonterminal = 1.0 - dones if dones is not None else 1.0
    delta = rho * (rewards + gamma * v_next * nonterminal - values)

    acc, out = torch.zeros_like(bootstrap_value), torch.zeros_like(values)
    for t in reversed(range(len(rewards))):
        acc = delta[t] + gamma * c[t] * nonterminal[t] * acc
        out[t] = acc
    return values + out
```
