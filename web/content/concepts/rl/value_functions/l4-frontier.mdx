## The founding idea

<PaperCard refKey="sutton1988td" />

Temporal-difference learning is the proposal that you can learn a prediction by
regressing it toward your own *later* prediction, rather than waiting for the
actual outcome. Every value function trained since is a variation on this, and
the 1988 paper's convergence proof for the linear case is the last time the
guarantees were unconditional.

## Changing the architecture, and the scale

<PaperGrid>
<PaperCard refKey="wang2016dueling" />
<PaperCard refKey="vanhasselt2016popart" />
</PaperGrid>

Dueling is a statistical efficiency argument. In most states the action choice
barely matters — the state's value dominates and the action differences are
small. A flat $Q$ head has to learn that shared value separately in every
action's output; splitting the streams learns it once, so every transition
improves the value estimate regardless of which action was taken. The
normalisation term exists because the decomposition is otherwise unidentifiable.

PopArt attacks something less glamorous and arguably more consequential. Value
targets span orders of magnitude across tasks and across training, and the
standard workaround had been reward clipping — which quietly changes the
objective, making a reward of 1000 indistinguishable from one of 1. PopArt
normalises adaptively and simultaneously adjusts the output layer's weights so
the function the network represents is unchanged by the rescaling.

<KeyIdea>
Two very different kinds of contribution sit here. One changes what the network
computes; the other changes nothing about the estimator and fixes a numerical
problem that had been distorting what everybody was optimising. The second kind
is less cited and, when you are debugging your own system, more often the one
you need.
</KeyIdea>

## Changing the object

<PaperCard refKey="bellemare2017distributional" />

Instead of $Q(s,a)$ as a number, learn $Z(s,a)$ as a distribution over returns,
and push the whole distribution through the Bellman operator — shift by $r$,
shrink by $\gamma$, project back onto a fixed set of atoms. The distributional
operator is a contraction in the Wasserstein metric, so the theory is intact.

The interesting part is that the policy still acts on the mean, and the gains
are large anyway. The usual explanation is that predicting a distribution is a
richer auxiliary task that shapes better features. That is an explanation, not a
settled result, and saying so is more honest than repeating it as fact.

## Making value learning work off-policy at scale

<PaperCard refKey="espeholt2018impala" />

Once actors are distributed, their trajectories arrive under slightly stale
policies, and the TD residual is only a valid signal for the policy that
generated the transition. V-trace applies truncated importance weights, with two
separate clipping thresholds that bound the bias of the fixed point and the
variance of the update independently. Structurally it is the same backward
recursion as GAE, extended to survive being off-policy.

## The concern that is not about the estimator

<PaperGrid>
<PaperCard refKey="kumar2021iup" />
<PaperCard refKey="lyle2022capacity" />
</PaperGrid>

This is the most useful recent shift and it is under-taught. A value network is
not solving one regression problem; it is solving a long sequence of them, each
initialised from the previous solution, against targets that move because the
policy improves. That process degrades the network itself: the feature matrix
drifts toward low effective rank, and the model progressively loses the ability
to fit new targets. The architecture that fit fine at ten thousand steps cannot
at ten million.

<Warning>
Nothing in the Bellman machinery addresses this, which is why it is worth
knowing separately. The symptom is distinctive: a late-training plateau that is
insensitive to learning rate, capacity, and $\lambda$, on a run that was
learning normally earlier. The mitigations are also unlike anything else on this
page — periodic resets of some layers, regularisation toward the initial random
features, and larger update-to-data ratios paired with resets. If someone asks
what is currently limiting deep value-based RL, this is a better answer than
overestimation.
</Warning>
