## Why it is a problem at all

Supervised learning gets a label for every input. Reinforcement learning gets a
reward only for the action it took — and the action it took came from the policy
it currently believes in.

That circularity is the whole problem. A policy that has settled on a mediocre
strategy generates data that confirms the mediocre strategy is fine, because it
never generates data about anything else.

<Intuition>
You move to a new city and try one restaurant. It is decent. Go back and you
reliably get a decent meal; try somewhere new and you might get worse. Follow
"pick the best known option" strictly and you eat at the same decent restaurant
for a decade, never learning that the place two streets over is superb.

Now make it harder. The superb place is at the end of an unmarked alley, three
turns in, and every wrong turn puts you back on the main street. Wandering
randomly will not find it — not because you are unlucky, but because random
wandering does not *commit* to going anywhere.
</Intuition>

## Two kinds of exploration

        caption="The chain makes the distinction concrete. Per-step randomness has to guess right N times running; an uncertainty bonus that propagates through value backups pulls the agent forward deliberately." />

<Steps>
<Step title="Undirected: add noise">
$\epsilon$-greedy, Gaussian action noise, an entropy bonus. Cheap, universal,
and it works whenever the good behaviour is a small perturbation of the current
one. The randomness is redrawn every step, so it produces a random walk.
</Step>

<Step title="Directed: go where you are uncertain">
Track what you have not seen — visit counts, an ensemble's disagreement, a
novelty score — and add it to the reward or use it to pick actions. Crucially,
because it enters the reward, value backups carry it backwards: states that
*lead to* unexplored regions become valuable, so the agent walks toward the
frontier instead of stumbling near it.
</Step>

<Step title="Posterior sampling: commit for a while">
Sample one plausible value function and act greedily on it for an entire
episode. Different samples produce different coherent strategies, which is
temporally extended exploration without needing an explicit bonus. Bootstrapped
DQN is the practical version.
</Step>
</Steps>

<KeyIdea>
The difference is **temporal extent**. Per-step noise cannot execute a plan it
does not already have. Anything that propagates — a bonus through value backups,
or a sampled value function held fixed for an episode — can. Raising $\epsilon$
does not help and actively hurts: it makes each step more random, so an $N$-step
correct sequence becomes *less* likely.
</KeyIdea>

## The trap in curiosity

The obvious directed method is to reward the agent for surprising itself: keep a
forward model, and pay out where its predictions are worst.

<Warning>
This has a famous failure called the **noisy TV**. Put a screen showing random
static in the environment. Its next frame is genuinely unpredictable, so the
prediction error never falls, so the bonus never runs out — and the agent sits
watching static forever, maximising its intrinsic reward perfectly.

The confusion is between *epistemic* uncertainty (things you have not learned
yet, which shrink with data) and *aleatoric* noise (things that are inherently
random and never shrink). Prediction error measures their sum. Random Network
Distillation's fix is to make the prediction target a fixed randomly-initialised
network applied to the observation — a deterministic function, so there is no
irreducible noise, and the error really does go to zero on states you have
visited enough.
</Warning>

## What actually happens on robots

Most of this literature is evaluated where a million episodes is affordable. On
a real arm, a few hundred episodes is a good day, and an exploring policy is a
policy doing unpredictable things with a heavy machine.

So the practical answer in robot learning is usually to **remove** the
exploration problem rather than solve it: start from demonstrations so the
policy is already competent, use scripted resets so episodes are cheap, and
apply RL for local fine-tuning where the search is small. Knowing the methods
and knowing they are rarely deployed on hardware is a more useful thing to say
than either half alone.
