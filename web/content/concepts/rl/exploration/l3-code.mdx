## RND end to end

<CodeWalk title="Random Network Distillation">

```python title="rnd.py"
import torch, torch.nn as nn

class RND(nn.Module):
    def __init__(self, obs_dim, feat_dim=128, hidden=256):
        super().__init__()
        # The target is random and FROZEN. Its whole job is to be a fixed,
        # deterministic, guaranteed-learnable function of the observation.
        self.target = nn.Sequential(
            nn.Linear(obs_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, feat_dim),
        )
        for p in self.target.parameters():
            p.requires_grad_(False)

        self.predictor = nn.Sequential(
            nn.Linear(obs_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, feat_dim),
        )

        # Running stats: observations in, intrinsic returns out.
        self.register_buffer("obs_mean", torch.zeros(obs_dim))
        self.register_buffer("obs_var", torch.ones(obs_dim))
        self.register_buffer("int_ret_std", torch.ones(()))

    def _norm_obs(self, obs):
        # A random network's output scale is arbitrary, so raw inputs make the
        # error dominated by whichever feature has the largest units.
        return ((obs - self.obs_mean) / self.obs_var.sqrt().clamp(min=1e-6)).clamp(-5, 5)

    def intrinsic_reward(self, obs):
        z = self._norm_obs(obs)
        with torch.no_grad():
            err = (self.predictor(z) - self.target(z)).pow(2).mean(-1)
        # Scale changes by orders of magnitude over training; without this,
        # beta is an uncontrolled schedule rather than a hyperparameter.
        return err / self.int_ret_std.clamp(min=1e-6)

    def loss(self, obs):
        z = self._norm_obs(obs)
        return (self.predictor(z) - self.target(z).detach()).pow(2).mean()
```

</CodeWalk>

Three lines carry the method. `requires_grad_(False)` on the target is the
method — a trained target would make the error measure the target's drift rather
than the agent's familiarity. The observation normalisation matters more than it
looks, because a random network's output scale is set by its inputs and nothing
else. And dividing by the running intrinsic-return standard deviation is what
turns $\beta$ into a hyperparameter instead of a schedule.

## Two value heads

```python title="agent.py"
class TwoStreamCritic(nn.Module):
    """Extrinsic reward is episodic; intrinsic is not.

    A state's novelty does not stop mattering because an episode ended.
    Treating the intrinsic stream episodically makes the agent act as if
    dying resets the world's unexploredness — which discourages exactly the
    risky exploration the bonus is paying for.
    """
    def __init__(self, obs_dim, hidden=256):
        super().__init__()
        self.trunk = nn.Sequential(nn.Linear(obs_dim, hidden), nn.Tanh())
        self.v_ext = nn.Linear(hidden, 1)
        self.v_int = nn.Linear(hidden, 1)

    def forward(self, obs):
        h = self.trunk(obs)
        return self.v_ext(h).squeeze(-1), self.v_int(h).squeeze(-1)


# Separate GAE per stream, then combine the advantages.
adv_ext = gae(r_ext, v_ext, dones, gamma=0.999, lam=0.95)   # long, episodic
adv_int = gae(r_int, v_int, dones=None, gamma=0.99, lam=0.95)  # shorter, non-episodic
advantages = adv_ext + beta * adv_int
```

<Warning>
Adding an intrinsic bonus changes the MDP you are solving, and the change is
**non-stationary** — the bonus decays as states become familiar, so the value
function is chasing a target that moves for reasons unrelated to policy
improvement. Either anneal $\beta$ so the final policy optimises the real
reward, or keep the streams separate as above and be explicit that the deployed
objective is the extrinsic head.
</Warning>

## The cheaper options, and when they are enough

<Steps>
<Step title="Entropy bonus (already in SAC, PPO)">
One line, no extra networks, and it is the right tool whenever the good
behaviour is a perturbation of the current one. It is undirected, so it will not
solve a chain — but most tasks are not chains.
</Step>

<Step title="Ensemble disagreement">
Train $M$ critics on bootstrapped data and use their standard deviation as the
bonus, or sample one per episode and act greedily on it. Simpler than a density
model, and the per-episode variant gives temporally extended exploration for
almost no code.
</Step>

<Step title="Then RND">
Reach for it when the reward is genuinely sparse and the state space is large
enough that counts are meaningless. It brings two networks, three
normalisations, and a coefficient — real complexity, worth paying only when the
cheaper options have visibly failed.
</Step>
</Steps>

## Measuring whether it is working

```python title="diagnostics.py"
# State coverage beats intrinsic-reward magnitude as a metric: the bonus can
# be large simply because the predictor is undertrained, which says nothing
# about whether the agent is reaching new places.
def coverage(visited_states, grid=64):
    """Fraction of a discretised state space touched this run."""
    keys = {tuple((s * grid).astype(int)) for s in visited_states}
    return len(keys) / (grid ** visited_states.shape[1])

# For a hard-exploration task, the honest metric is progress-based:
#   - furthest room / stage / milestone reached
#   - number of distinct milestones hit at least once
# Mean episode return hides everything, because it stays at zero right up
# until exploration succeeds and then jumps.
```

<KeyIdea>
Mean return is the wrong curve for a hard-exploration problem. It is flat at
zero while exploration is failing *and* while it is nearly succeeding, so it
carries no gradient of information for you as the engineer. Track coverage or
milestone counts, which move continuously and tell you whether to keep going.
</KeyIdea>
