## The full update, with both classic stabilizers

<CodeWalk title="DQN training step (replay + target network + Double-DQN target)">

```python title="dqn_update.py"
import torch
import torch.nn.functional as F

def dqn_update(q_net, q_target, buffer, opt,
               batch_size=256, gamma=0.99, double=True):
    obs, action, reward, obs2, done = buffer.sample(batch_size)

    with torch.no_grad():
        if double:
            # Double DQN: online net SELECTS, target net EVALUATES.
            a_star = q_net(obs2).argmax(dim=1, keepdim=True)
            next_q = q_target(obs2).gather(1, a_star)
        else:
            next_q = q_target(obs2).max(dim=1, keepdim=True).values
        y = reward + gamma * (1.0 - done) * next_q          # (B, 1)

    q_taken = q_net(obs).gather(1, action)                  # Q(s, a_logged)
    loss = F.smooth_l1_loss(q_taken, y)                     # Huber: robust to outlier TD errors

    opt.zero_grad()
    loss.backward()
    torch.nn.utils.clip_grad_norm_(q_net.parameters(), 10.0)
    opt.step()
    return loss.item()

```

The two stabilizers earn their keep against specific failure modes:
**replay** breaks the temporal correlation that makes SGD on sequential
transitions thrash; the **target network** freezes the regression target so
you're not chasing your own update.

</CodeWalk>

<KeyIdea>

DQN = sampled Bellman optimality backup + two patches for the deadly triad
(replay decorrelates, target nets slow the moving target) + one patch for
max-bias (Double). Each line of the update exists to counter a named
instability — be able to say *which*.

</KeyIdea>

<Warning>

Debug order when DQN flatlines: (1) print `Q.mean()` — if it climbs into the
hundreds on a reward-clipped env, your target/Double logic is wrong;
(2) check the `(1-done)` mask on truncation vs termination; (3) verify
replay stores `obs2` *after* the step (off-by-one corrupts every target);
(4) only then touch hyperparameters.

</Warning>
