## Q-learning, with a network

Tabular Q-learning keeps a number for every state-action pair and updates it
toward $r + \gamma\max_{a'}Q(s',a')$. It has convergence guarantees and it is
useless for anything with more states than you can enumerate.

DQN replaces the table with a convolutional network taking raw pixels. The
update rule is unchanged. That substitution alone does not work — and the
interesting content of DQN is what had to be added to make it work.

<Intuition>
Learning a game by keeping a running opinion of how good each button is in each
situation. Press the button you currently think is best, see what happens,
revise.

The awkward part is that your opinion about *this* situation is derived from
your opinion about the *next* one — which you are also revising, using this one.
Everyone is quoting everyone else's estimate, and nothing is anchored.
</Intuition>

## Why it does not work naively

Two correlations wreck it, and DQN's two famous components each remove one.

<Figure src="/figures/dqn-decorrelation.svg"
        alt="Top: consecutive near-identical frames feeding a single network that both predicts and sets its own target. Bottom left: a replay buffer with a batch sampled from across the whole history. Bottom right: an online network and a periodically-copied frozen target network."
        caption="Two different correlations, two different fixes. Conflating them is the standard mistake — replay decorrelates samples from each other, the target network decorrelates the prediction from what it is chasing." />

<Steps>
<Step title="Consecutive samples are near-duplicates">
Four frames from one second of gameplay are essentially one observation.
Gradient descent behaves as if the batch is a sample of the data distribution,
and here it is a sample of the last second — so the network overfits to the
present moment and loses competence everywhere else.
</Step>

<Step title="The replay buffer fixes it">
Store a million transitions; draw each batch uniformly at random. A batch now
spans hours of experience, and it lets each transition be reused many times,
which is a large sample-efficiency win as a side effect.
</Step>

<Step title="The target moves because you moved">
The regression target is $r + \gamma\max_{a'}Q_\theta(s',a')$, computed with the
network you are updating. Change $\theta$ to fit one state and you have changed
the target for every state — you are chasing something that runs when you
approach it.
</Step>

<Step title="The frozen target network fixes it">
Keep a copy $Q_{\theta^-}$, updated by copying $\theta$ every few thousand steps.
Compute targets with the copy. The thing being chased now holds still long
enough to be caught, which turns an unstable feedback loop into a sequence of
ordinary regression problems.
</Step>
</Steps>

<KeyIdea>
The stabilisers *are* the contribution. Neural function approximation of $Q$ was
not new in 2013; making it not diverge was. Both fixes are answers to the deadly
triad — bootstrapping, function approximation, and off-policy data have no
convergence guarantee together — and neither removes the problem. They separate
timescales so the failure happens slowly enough to outrun.
</KeyIdea>

## The limitation that shaped everything after

Acting requires $\arg\max_a Q(s,a)$. With eighteen Atari buttons that is an
eighteen-way comparison. With a 7-DoF arm's continuous torques it is a nonconvex
optimisation problem you would have to solve at every control step.

<Warning>
This is why DQN is not a robotics algorithm as written, and why the entire
continuous-control literature looks the way it does. DDPG, TD3, and SAC all
train an actor network whose job is to *approximate the argmax* so it can be
evaluated in one forward pass. QT-Opt took the alternative route and ran a
cross-entropy-method optimisation over the action space at every step — it
worked, on real robot grasping, and its cost is a fair measure of how binding
the constraint is.
</Warning>

There is one more thing worth knowing before you trust a $Q$-value. The max over
noisy estimates is upward-biased — it selects whichever action's error happened
to be positive — and bootstrapping propagates that inflation backwards. Double
DQN fixes it in one line by using the online network to *select* the action and
the target network to *evaluate* it, so the two noises are independent. Level 2
derives why that works.
