## REINFORCE in ~50 lines

The simplest policy-gradient agent that actually works. Everything later
(A2C, PPO) is this file plus variance reduction.

<CodeWalk title="REINFORCE with a running-mean baseline on CartPole">

```python title="reinforce.py"
import torch
import torch.nn as nn
import gymnasium as gym
from torch.distributions import Categorical

env = gym.make("CartPole-v1")
policy = nn.Sequential(
    nn.Linear(4, 128), nn.Tanh(),
    nn.Linear(128, 2),                       # logits over 2 actions
)
opt = torch.optim.Adam(policy.parameters(), lr=1e-3)
gamma, baseline = 0.99, 0.0

for episode in range(2000):
    obs, _ = env.reset()
    logps, rewards = [], []
    done = False
    while not done:
        dist = Categorical(logits=policy(torch.as_tensor(obs)))
        action = dist.sample()               # stochastic — this IS exploration
        logps.append(dist.log_prob(action))
        obs, r, term, trunc, _ = env.step(action.item())
        rewards.append(r)
        done = term or trunc

    # Returns-to-go: G_t = r_t + gamma * G_{t+1}
    G, returns = 0.0, []
    for r in reversed(rewards):
        G = r + gamma * G
        returns.append(G)
    returns = torch.tensor(returns[::-1])

    baseline = 0.95 * baseline + 0.05 * returns.mean()   # cheap baseline
    advantage = returns - baseline                        # no grad by construction

    loss = -(torch.stack(logps) * advantage).sum()
    opt.zero_grad()
    loss.backward()
    opt.step()
```

Three load-bearing details: the action is **sampled** (exploration lives in
the policy itself); the weight on each `logp` is **return-to-go**, so actions
aren't credited for rewards that preceded them; and the baseline is
subtracted **without** participating in the graph.

</CodeWalk>

## The one-line generalization

Every on-policy method is this loss with a better `advantage`:

```python
loss = -(logp * advantage).mean()      # REINFORCE: advantage = G - b
                                       # A2C:       advantage = r + γV(s') - V(s)
                                       # PPO:       same, but ratio-clipped + GAE
```

<KeyIdea>

`logp * advantage.detach()` is the entire genome of on-policy RL. Memorize
the gradient-flow picture: ∂loss/∂θ touches only the policy network through
`logp`; the advantage is a frozen score that says *push this action's
probability up or down, this hard*.

</KeyIdea>

<Warning>

REINFORCE's gradient variance grows with horizon — on anything harder than
CartPole, raw REINFORCE needs millions of episodes. That's not a bug to fix
with tuning; it's the motivation to graduate to actor-critic (learned
baseline, TD bootstrapping) and GAE. If your "PPO" runs worse than this
script, you've almost certainly broken advantage normalization or detach.

</Warning>
