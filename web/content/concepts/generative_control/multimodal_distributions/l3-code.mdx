## Is your data even multimodal?

<CodeWalk title="Condition first — the marginal tells you nothing">

```python title="detect.py"
import numpy as np
from sklearn.neighbors import NearestNeighbors

def conditional_spread(obs_emb, actions, k=25, sample=2000, seed=0):
    """Multimodality is a property of p(a | o). The marginal p(a) is broad in
    every robot dataset simply because the task has phases, so a histogram of
    all actions is not evidence of anything.

    Returns per-query action spread among observation-space neighbours, which
    localises WHERE a regression head will fail rather than giving a
    dataset-level verdict.
    """
    nn = NearestNeighbors(n_neighbors=k).fit(obs_emb)
    rng = np.random.default_rng(seed)
    idx = rng.choice(len(obs_emb), size=min(sample, len(obs_emb)), replace=False)

    out = []
    for i in idx:
        _, nbr = nn.kneighbors(obs_emb[i : i + 1])
        A = actions[nbr[0]]
        # Spread of neighbours' actions relative to their own mean. Large values
        # mean the expert disagreed with itself at nearly the same observation.
        out.append(np.linalg.norm(A - A.mean(0), axis=1).mean())
    return np.array(out)
```

</CodeWalk>

Rank observations by this score and look at the top ones. They are the states
where the expert was inconsistent, and the states where an MSE head will output
something nobody demonstrated.

## A mixture head, without the collapse

<CodeWalk title="Mixture density network">

```python title="mdn.py"
import torch, torch.nn as nn

class MDNHead(nn.Module):
    """Models the JOINT action with K components. Independent per-dimension
    heads would match every marginal and still put half their mass on
    combinations that never occurred."""

    def __init__(self, in_dim, act_dim, k=8, min_log_sigma=-4.0):
        super().__init__()
        self.k, self.act_dim, self.min_log_sigma = k, act_dim, min_log_sigma
        self.head = nn.Linear(in_dim, k * (1 + 2 * act_dim))

    def forward(self, h):
        o = self.head(h)
        logits = o[:, : self.k]
        mu = o[:, self.k : self.k + self.k * self.act_dim].view(-1, self.k, self.act_dim)
        log_sigma = o[:, self.k + self.k * self.act_dim :].view(-1, self.k, self.act_dim)
        # The Gaussian log-likelihood contains -log(sigma), unbounded below as
        # sigma -> 0. Without this clamp a component collapses onto a few points
        # for infinite likelihood and starves the others — the standard failure.
        return logits, mu, log_sigma.clamp_min(self.min_log_sigma)

    def nll(self, h, a):
        logits, mu, log_sigma = self(h)
        d = (a.unsqueeze(1) - mu) / log_sigma.exp()
        # Per-component log-prob, summed over action dims (a JOINT Gaussian).
        comp = (-0.5 * d.pow(2) - log_sigma).sum(-1)
        # logsumexp over components, in log space — computing this with exp()
        # underflows as soon as one component fits well.
        return -torch.logsumexp(torch.log_softmax(logits, -1) + comp, dim=-1).mean()
```

</CodeWalk>

## The check that actually has power

<CodeWalk title="Compare the joint, not the marginals">

```python title="check.py"
import numpy as np
from sklearn.neighbors import NearestNeighbors

def joint_support(policy_samples, demo_actions, radius=None):
    """Fraction of sampled actions with NO demonstrated action nearby.

    Per-dimension histograms cannot detect the factorisation failure, because a
    product of marginals matches every marginal by construction. This compares
    the joint: a sample in a region with no demonstrations is an action the
    expert never took, however plausible each of its components looks.
    """
    nn = NearestNeighbors(n_neighbors=1).fit(demo_actions)
    d, _ = nn.kneighbors(policy_samples)
    if radius is None:
        # Scale-free default: the typical demo-to-demo spacing.
        dd, _ = NearestNeighbors(n_neighbors=2).fit(demo_actions).kneighbors(demo_actions)
        radius = 3.0 * np.median(dd[:, 1])
    return float((d[:, 0] > radius).mean()), radius


def mode_coverage(policy, obs, n=256):
    """Does the policy produce BOTH modes at one observation, or commit to one?
    Sample repeatedly at a fixed observation and cluster the results —
    a policy that always returns the same action has not solved multimodality,
    it has picked a mode."""
    A = np.stack([policy.sample(obs) for _ in range(n)])
    return A.std(0), A
```

</CodeWalk>

<KeyIdea>
`mode_coverage` catches the failure people miss in the other direction. A policy
that deterministically commits to one mode looks excellent on rollout success
whenever either mode works, and fails silently when the choice is
context-dependent — approaching from the left is right only when the right side
is blocked. Checking that samples at a fixed observation are actually diverse is
what distinguishes "represents the distribution" from "picked a mode and got
lucky".
</KeyIdea>

<Warning>
Run `joint_support` on your training data first to calibrate: demonstrations
compared against themselves should score near zero at your chosen radius. If they
do not, the radius is too tight and every result afterwards will be
uninterpretable. This is the sort of check that costs two minutes and prevents an
afternoon of chasing a threshold artefact.
</Warning>
