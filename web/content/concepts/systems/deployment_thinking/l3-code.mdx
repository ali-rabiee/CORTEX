## The loop

<CodeWalk title="Fixed-rate control, asynchronous inference">

```python title="deploy.py"
import threading, time
from dataclasses import dataclass

@dataclass
class Stamped:
    value: object
    t: float          # when the underlying measurement was taken, not when stored


class InferenceWorker:
    """Runs the policy off the control thread and keeps ONLY the newest result.

    A queue is wrong here: under load it delivers increasingly stale actions
    while throughput still looks healthy. Dropping bounds staleness by
    construction.
    """

    def __init__(self, policy):
        self.policy = policy
        self._pending = None          # at most one request, always the newest
        self._latest = None           # at most one result
        self._lock = threading.Lock()
        self._cv = threading.Condition(self._lock)
        threading.Thread(target=self._run, daemon=True).start()

    def submit(self, obs: Stamped):
        with self._cv:
            self._pending = obs       # overwrite: drop whatever was waiting
            self._cv.notify()

    def latest(self) -> Stamped | None:
        with self._lock:
            return self._latest

    def _run(self):
        while True:
            with self._cv:
                while self._pending is None:
                    self._cv.wait()
                obs, self._pending = self._pending, None
            actions = self.policy(obs.value)
            with self._lock:
                # Stamped with the OBSERVATION's time, so staleness is measured
                # from when the world was seen, not from when we finished.
                self._latest = Stamped(actions, obs.t)
```

</CodeWalk>

The `_latest` result is stamped with the *observation's* timestamp, not the
completion time. Staleness has to be measured from when the world was seen —
stamping at completion makes a slow inference look fresh, which is precisely
backwards.

## The control thread

<CodeWalk title="A loop that never blocks, and always has a behaviour">

```python title="control.py"
MAX_STALENESS_S = 0.25     # derived from the task bandwidth, not picked
CONTROL_HZ = 20

def control_loop(robot, worker, chunk_len=8):
    period = 1.0 / CONTROL_HZ
    next_tick = time.perf_counter()
    chunk, chunk_idx, chunk_t = None, 0, -1e9

    while robot.enabled:
        now = time.perf_counter()

        obs = robot.read_observation()             # already Stamped
        if now - obs.t > MAX_STALENESS_S:
            robot.safe_stop("stale observation")   # a defined behaviour
            return

        worker.submit(obs)                         # never blocks

        fresh = worker.latest()
        if fresh is not None and fresh.t > chunk_t:
            chunk, chunk_idx, chunk_t = fresh.value, 0, fresh.t

        if chunk is None or chunk_idx >= chunk_len:
            # No action available, or the chunk is exhausted. Do not block —
            # blocking turns a latency problem into unbounded loss of control.
            if now - chunk_t > MAX_STALENESS_S:
                robot.safe_stop("no fresh action")
                return
            robot.hold()
        else:
            robot.command(chunk[chunk_idx])
            chunk_idx += 1

        next_tick += period
        sleep_for = next_tick - time.perf_counter()
        if sleep_for > 0:
            time.sleep(sleep_for)
        else:
            METRICS.deadline_miss.inc()            # count these; they are the tail
            next_tick = time.perf_counter()        # do not accumulate lateness
```

</CodeWalk>

<Warning>
`next_tick = time.perf_counter()` after a miss matters. Without it, a single
overrun leaves the loop permanently behind schedule and it spends the next
several cycles running with no sleep at all, trying to catch up — converting one
late cycle into a burst of them.
</Warning>

## Measuring the tail

```python title="metrics.py"
class LatencyTracker:
    """Report percentiles. The mean tells you nothing about whether the loop
    holds — a 40 ms median with a 250 ms p99 against a 100 ms period misses at
    least 1% of cycles, which is 720 per hour at 20 Hz."""

    def __init__(self, window=10_000):
        self.samples = collections.deque(maxlen=window)

    def record(self, seconds):
        self.samples.append(seconds)

    def report(self, period):
        a = np.array(self.samples)
        return {
            "p50": float(np.percentile(a, 50)),
            "p95": float(np.percentile(a, 95)),
            "p99": float(np.percentile(a, 99)),
            "max": float(a.max()),
            "miss_rate": float((a > period).mean()),
            "misses_per_hour": float((a > period).mean() * 3600 / period),
        }
```

## Version the whole tuple

```python title="version.py"
@dataclass(frozen=True)
class DeployedPolicy:
    weights_sha: str
    preprocess_sha: str        # resize, crop, colour handling
    norm_stats_sha: str        # action mean/std — a silent killer when stale
    calibration_sha: str       # camera intrinsics and extrinsics
    decode_params_sha: str     # action bin edges, chunk length, T_a
    control_params_sha: str    # rate, gains, staleness bound

    def fingerprint(self) -> str:
        blob = "|".join(astuple(self))
        return hashlib.sha256(blob.encode()).hexdigest()[:12]


# Every rollout log line carries the fingerprint. When two results disagree,
# "same system?" becomes a one-second comparison instead of a day.
```

<KeyIdea>
The most expensive deployment bug is "the new policy is worse" where the weights
did not change — normalisation statistics recomputed on a newer dataset
revision, a camera recalibrated, a gripper firmware update that rescaled the
command. A checkpoint name records none of that. The fingerprint does.
</KeyIdea>

## Watch the inputs, not only the outputs

```python title="monitor.py"
class InputMonitor:
    """Success rate tells you it broke. Input statistics tell you before.

    Track the same summary you tracked over the training set, and alert on
    drift — the lighting changed, a camera drifted, the object set is
    different from last month.
    """

    def __init__(self, encoder, train_embeddings, k=5):
        self.encoder = encoder
        self.index = build_index(train_embeddings)
        self.k = k

    def check(self, obs):
        z = normalize(self.encoder(obs))
        sims, _ = self.index.search(z[None].astype("float32"), self.k)
        ood_distance = 1.0 - float(sims.mean())
        return {
            "ood_distance": ood_distance,
            "flag": ood_distance > OOD_THRESHOLD,   # calibrated on held-out data
            "brightness": float(obs.mean()),
            "saturated_frac": float((obs > 250).mean()),
        }
```

## The checklist before anything runs unsupervised

<Steps>
<Step title="Every input is timestamped and staleness-checked">
Including proprioception. A stale joint reading is as dangerous as a stale
image and much less likely to be noticed.
</Step>

<Step title="Every failure path has been executed, not just written">
Unplug the camera while it runs. Kill the inference process. Add 500 ms of
artificial latency. A fallback that has never been triggered is a hypothesis.
</Step>

<Step title="Deadline misses and OOD flags are counted and visible">
Both are leading indicators. Neither shows up in a success rate until after it
has cost you something.
</Step>

<Step title="Rollback takes under a minute">
The new policy is worse in some situation you did not test. Being able to revert
quickly is worth more than confidence that it will not happen.
</Step>
</Steps>
