## Failure modes

Optimized model has different behavior: quantization changes numerical outputs enough to affect policy behavior. Symptoms: policy works in FP32 but fails in FP16/INT8 — subtle action differences compound over a trajectory. Fix: calibrate quantization on representative data, validate post-optimization on full evaluation suite, use mixed-precision (sensitive layers in FP32).

## Interview-ready answer

Latency optimization is critical for deploying learned robot policies. My optimization stack: (1) algorithmic — reduce denoising steps with DDIM/consistency models, (2) numerical — FP16 inference, mixed precision where needed, (3) compilation — TensorRT/ONNX for GPU, TFLite for edge, (4) architectural — async pipelines so inference runs in parallel with execution. Key insight: it's often better to use a smaller, faster model with slightly lower accuracy than a large slow one — the control bandwidth improvement more than compensates. Target latencies: $< 50\,\text{ms}$ for pick-and-place, $< 10\,\text{ms}$ for contact-rich tasks, $< 1\,\text{ms}$ for joint-level reactive control.
